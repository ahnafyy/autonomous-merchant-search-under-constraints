# UCP Input Data

This directory contains public-safe metadata and immutable snapshot manifests for the
UCP experiment. Do not store API keys, bearer tokens, cookies, or raw credentials.

Start with `inventory.example.json`. Each endpoint record names an authentication
environment variable, never its value. An endpoint is eligible for live collection
only when its permission status is verified, its selected operation is side-effect
free, and it supports exact-product lookup.

Raw live responses may be retained only when endpoint terms permit it. Generated
research artifacts should identify an immutable input snapshot by ID and hash rather
than copying restricted payloads.

## Candidate files

`candidates-2026-04-02.json` was produced by `scripts/build_ucp_inventory.py` from a
third-party scan of domains' `.well-known/ucp` endpoints. The scan's `verified` status
means the endpoint returned a schema-valid UCP capability document; it does not mean
this project has confirmed permission to collect from that merchant, nor that any
operation is side-effect free. Every entry in this file is therefore written with
`permission_status: "unknown"`, `exact_product_lookup: false`, and
`side_effect_free: false`, so `screen_endpoint_inventory` excludes all of them.

Before any entry can be promoted into a research-eligible inventory:

1. Confirm the merchant's terms permit automated collection for this research.
2. Confirm the specific read operation used is exact-product lookup and side-effect
   free (this scan only reports checkout/order/cart capability flags, not a
   confirmed read-only operation).

## The `declared_capability` permission status

`permission_status` supports four values: `"verified"`, `"declared_capability"`,
`"unknown"`, and `"denied"`. Only `"verified"` and `"declared_capability"` pass
`screen_endpoint_inventory`.

`"declared_capability"` means: the merchant's public UCP discovery profile
(`/.well-known/ucp`) itself declares the exact read-only capability this project
invoked (for example `dev.ucp.shopping.catalog.search`), and we treat that public
declaration as the merchant's stated invitation for automated read-only queries of
exactly that capability -- consistent with UCP's stated purpose as a protocol for
agentic commerce. This is an explicit, documented modeling assumption, not a
case-by-case Terms-of-Service review or explicit merchant consent.

`"verified"` is reserved for endpoints with actual case-by-case confirmation (for
example a direct agreement with the merchant). Do not relabel a
`declared_capability` endpoint as `verified` without that stronger confirmation --
the distinction exists specifically so published claims can state which basis
applies to which merchant.

basis, covering merchants this project actually queried live via `search_catalog`
on 2026-08-02. See that script's docstring and `/memories/repo/ucp-protocol-facts.md`
