Run \texttt{make install}, \texttt{make build}, and \texttt{make check} from the
repository root to install dependencies, regenerate JSON, CSV, \LaTeX{}, site,
claim, and conformance artifacts, and verify both packages.  The npm checks cover
the planner and middleware against vectors generated by the canonical Python
implementation.  The analysis uses exact rational arithmetic; the hard-constraint
checks have no floating tolerance.  Generated manifests omit wall-clock timestamps
and record the configured seed
\ResultRandomSeed{}.

The current unit checks cover offer expiry, resource exhaustion, hard-cap
admissibility, budget-dependent Bellman actions, atomic reservation, exact
reclamation, conservative censored charging, one-time reconciliation,
commerce-domain validation, frozen-panel oracle metrics, endpoint-inventory
screening, panel construction from dated snapshots, reservation-price monotonicity
in stockout risk, the paired bootstrap, exhaustive policy enumeration against the
solver, deterministic artifact generation, and claim evaluation.  JavaScript receipt
parity remains a required check rather than a completed verification result.

Live UCP protocol probing (endpoint discovery and read-only catalog search) was run
against real merchant endpoints on two dates, producing the snapshots described in
Section~\ref{sec:benchmark}: \ResultMerchantsTargeted{} merchants targeted,
\ResultCatalogRows{} catalog listings, and \ResultCrossMerchantSkus{} SKUs offered by
more than one merchant.  Every included merchant carries a documented
declared-capability rather than case-by-case verified permission status, and only
read operations were used.  Two scans taken minutes apart returned byte-identical
output, so the snapshot comparison in Section~\ref{sec:benchmark} measures merchant
behaviour rather than scanner nondeterminism.
