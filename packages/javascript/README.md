# autonomous-shopping-optimizer

Browser-safe, dependency-free shopping decision utilities, checked against vectors
generated by the canonical Python implementation. It includes the recalled-search
formula used by the current study and a separate legacy no-recall hard-budget planner.

The host owns LLM calls, merchant tools, credentials, and purchase execution. This
package makes deterministic decisions; it never contacts a merchant.

## Recalled-search hook for LLM tool loops

Call `createRecalledSearchHook` after every seller reveal when the agent can retain
the best offer it has already seen. The hook implements:

```text
SEARCH iff feasible and E[max(best retained offer - next price, 0)] > inspection cost
```

Prices and API spend are integer USD minor units. Resource shadow prices may be
fractional numbers: `time_ms` is a duration in milliseconds whose shadow price is
minor units per second, and `tokens` is charged in minor units per thousand tokens.
The host calibrates next-price samples and remains responsible for dispatching tools,
enforcing actual budgets, and executing purchases.

```js
import { createRecalledSearchHook } from "autonomous-shopping-optimizer";

const afterOffer = createRecalledSearchHook({
  priceSamplesMinor: [8900, 9400, 10200, 11100],
  shadowPrices: { time_ms: 8, api_calls: 2 },
});

const decision = afterOffer({
  currentBestMinor: 10000,
  nextInspectionResources: { time_ms: 12000, api_calls: 1, api_cost_minor: 18 },
  remainingBudget: { time_ms: 45000, api_calls: 3, api_cost_minor: 100 },
});

if (decision.action === "SEARCH") await callSellerTool();
else await buyBestRetainedOffer();
```

`decideRecalledSearch` exposes the same calculation without closing over the calibrated
samples. Both return feasibility, expected saving, the full inspection-cost breakdown,
net value, and reservation price so an LLM host can log or render its decision.

### ChatGPT/OpenAI and Claude tool registration

`recalledSearchToolSchema()` returns a portable `{ name, description, input_schema }`
object, and `runRecalledSearchTool()` executes that payload. Adapt only the outer tool
envelope for the chosen provider.

```js
import {
  recalledSearchToolSchema,
  runRecalledSearchTool,
} from "autonomous-shopping-optimizer";

const schema = recalledSearchToolSchema();

// OpenAI Chat Completions-style registration:
const openaiTool = {
  type: "function",
  function: {
    name: schema.name,
    description: schema.description,
    parameters: schema.input_schema,
    strict: true,
  },
};

// Anthropic Messages-style registration:
const claudeTool = schema;

// When either model emits decide_recalled_search arguments:
const decision = runRecalledSearchTool(modelToolArguments);
```

The model is a caller, not the decision authority. Validate seller identity and the
same-product calibration sample before calling the tool, enforce actual tool permits
separately, and keep purchase authorization outside the model-tool loop.

## Legacy decision rule

```js
import { affordableQueries, closedFormReservationPrice } from "autonomous-shopping-optimizer";

// 1. Your budget is one number, not four: whichever resource runs out first binds.
const k = affordableQueries(
  { time: 30, tokens: 8000, api_calls: 6, api_cost: 12 },
  { time: 4, tokens: 900, api_calls: 1, api_cost: 2 },
);                                                    // -> 6

// 2. Accept below a fraction of the price range you expect.
const threshold = closedFormReservationPrice(8000, 12000, k);   // -> 8798, i.e. $87.98

if (observedPrice <= threshold) buy();
else queryNextMerchant();
```

The acceptance fractions come from `u(0) = 1`, `u(k+1) = u(k) - u(k)**2 / 2`, giving
`0.500, 0.375, 0.305, 0.258, ...`. The threshold *rises* as the budget drains, because
failing to buy costs more than overpaying.

This recursion is not new: it is the Cayley-Moser problem (Cayley 1875, Moser 1956).

If you have per-merchant price forecasts rather than a range, `reservationPrice` runs
the exact recurrence instead.

## Legacy planner boundary

The older `planShoppingDecision` API implements commit-or-continue semantics: after an
observed catalog offer, the host either attempts purchase immediately or continues
without retaining that offer. Do not substitute it for `decideRecalledSearch` when
the workflow retains the best revealed seller offer.

## Enforcing budgets

```js
import { PermitLedger } from "autonomous-shopping-optimizer";

const ledger = new PermitLedger({ time: 30, tokens: 9000, api_calls: 6, api_cost: 12 });
const reservation = ledger.reserve("merchant-a", { time: 10, tokens: 3000, api_calls: 2, api_cost: 4 });

// ... the host enforces every ceiling on reservation.permit, then dispatches ...

ledger.reconcile(reservation, {
  usage: { time: 4, tokens: 1000, api_calls: 1, api_cost: 2 },
  exactResources: ["api_calls"],   // everything else is charged at the permit
  status: "timeout",
});
```

The ledger deducts the whole permit before the call, reclaims capacity known to be
unused, and charges censored usage at the full permit. Overruns are prevented rather
than detected afterwards.

## Study boundary

The current paper evaluates recalled adaptive stopping versus costed search-all. At
zero inspection cost search-all is better; small positive-cost intervals can be
inconclusive; material declared inspection costs can favor adaptive stopping. The
runtime hook is a formula implementation, not a claim that its inputs reproduce the
paper's frozen merchant data or checkout outcomes.

## Also included

- `decideRecalledSearch` / `createRecalledSearchHook` — decide SEARCH or STOP after
  a retained-offer reveal using calibrated next-price samples and declared costs.
- `planShoppingDecision` — pick the next merchant and the buy/continue action under a
  hard budget vector and purchase-price cap.
- `AutonomousShoppingOptimizer` — a stateful loop wrapper, aliased as
  `ShoppingAgentMiddleware`.
- `simulatePolicy` — replay a fixed offer sequence under a named policy.
- `secretarySampleSize` -- the classical `n/e` rule, provided so it can be compared
  against the threshold rule rather than confused with it.

## Parity with Python

Python is the canonical implementation. This package is validated against
`artifacts/conformance/`, which Python generates; expected values are never duplicated
by hand. Python computes reservation prices and acceptance fractions in exact rational
arithmetic while JavaScript uses doubles, so numeric conformance is checked within the
tolerance recorded in those files. Integer results, such as the affordable-query
horizon, are compared exactly.

The vectors are generated under `artifacts/conformance/` by the Python build; the
JavaScript package never maintains a separate expected-value fixture.

The recalled-search hook, planner, middleware, closed-form rule, and permit ledger
all have JavaScript equivalents. The study pipeline (panel construction, policy
replay, bootstrap) remains Python-only, since it is research tooling rather than a
runtime API.

## Production boundary

The public runtime surface is `decideRecalledSearch`, `createRecalledSearchHook`,
`recalledSearchToolSchema`, `runRecalledSearchTool`, `PermitLedger`, and the legacy
planner APIs. The package contains no merchant clients, provider SDKs, credentials, or
network calls. Your host must provide trustworthy same-product calibration samples and
remain the sole authority for external tool calls and purchases.
