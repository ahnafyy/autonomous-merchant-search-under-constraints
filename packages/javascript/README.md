# autonomous-shopping-optimizer

Decide when an autonomous shopping agent should stop searching and buy. Browser-safe,
dependency-free, and checked against vectors generated by the canonical Python
implementation.

The host owns LLM calls, merchant tools, credentials, and purchase execution. This
package makes the decision; it never contacts a merchant.

## The decision rule

```js
import { affordableQueries, closedFormReservationPrice } from "autonomous-shopping-optimizer";

// 1. Your budget is one number, not four: whichever resource runs out first binds.
const k = affordableQueries(
  { time: 30, tokens: 8000, api_calls: 6, api_cost: 12 },
  { time: 4, tokens: 900, api_calls: 1, api_cost: 2 },
);                                                    // -> 6

// 2. Accept below a fraction of the price range you expect.
const threshold = closedFormReservationPrice(8000, 12000, k);   // -> 8798, i.e. $87.98

if (observedPrice <= threshold) buy();
else queryNextMerchant();
```

The acceptance fractions come from `u(0) = 1`, `u(k+1) = u(k) - u(k)**2 / 2`, giving
`0.500, 0.375, 0.305, 0.258, ...`. The threshold *rises* as the budget drains, because
failing to buy costs more than overpaying.

This recursion is not new: it is the Cayley-Moser problem (Cayley 1875, Moser 1956).

If you have per-merchant price forecasts rather than a range, `reservationPrice` runs
the exact recurrence instead.

## Enforcing budgets

```js
import { PermitLedger } from "autonomous-shopping-optimizer";

const ledger = new PermitLedger({ time: 30, tokens: 9000, api_calls: 6, api_cost: 12 });
const reservation = ledger.reserve("merchant-a", { time: 10, tokens: 3000, api_calls: 2, api_cost: 4 });

// ... the host enforces every ceiling on reservation.permit, then dispatches ...

ledger.reconcile(reservation, {
  usage: { time: 4, tokens: 1000, api_calls: 1, api_cost: 2 },
  exactResources: ["api_calls"],   // everything else is charged at the permit
  status: "timeout",
});
```

The ledger deducts the whole permit before the call, reclaims capacity known to be
unused, and charges censored usage at the full permit. Overruns are prevented rather
than detected afterwards.

## Is it worth using?

The repository's calibrated simulation sweep reports evidence, not a universal
deployment prescription:

| Simulation condition | Evidence against the tuned fixed rule |
| --- | --- |
| Price spread at or below 1.01× | No cell favors adaptive stopping |
| Modest 1.10× spread | Fixed rule wins in two cells, at both constrained and full budgets |
| Larger spread in selected cells | Adaptive stopping is favored |

The table is simulation calibrated to the measured corpus, not a measurement of retail
outcomes. Each row includes its paired interval and sample size in the generated paper
and site tables. In the replay model, a catalog offer is accepted for an immediate
purchase attempt or not reserved; a later query is a new observation.

## Also included

- `planShoppingDecision` — pick the next merchant and the buy/continue action under a
  hard budget vector and purchase-price cap.
- `AutonomousShoppingOptimizer` — a stateful loop wrapper, aliased as
  `ShoppingAgentMiddleware`.
- `simulatePolicy` — replay a fixed offer sequence under a named policy.
- `secretarySampleSize` -- the classical `n/e` rule, provided so it can be compared
  against the threshold rule rather than confused with it.

## Parity with Python

Python is the canonical implementation. This package is validated against
`artifacts/conformance/`, which Python generates; expected values are never duplicated
by hand. Python computes reservation prices and acceptance fractions in exact rational
arithmetic while JavaScript uses doubles, so numeric conformance is checked within the
tolerance recorded in those files. Integer results, such as the affordable-query
horizon, are compared exactly.

The planner, middleware, closed-form rule, and permit ledger all have JavaScript
equivalents. The study pipeline (panel construction, policy replay, bootstrap) remains
Python-only, since it is research tooling rather than a runtime API.
