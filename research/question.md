# Research Question

## The Practical Problem

An agent that shops on a user's behalf has to decide, after every merchant it
queries, whether to buy what it just found or keep looking. Keeping going can find
a cheaper price. It also burns wall-clock time, model tokens, API calls, and money,
and it risks losing an offer that was purchasable a moment ago.

Engineers building these agents today pick a fixed rule: query three merchants, or
spend at most thirty seconds, or accept anything under a threshold. Nobody knows
when those fixed rules are good enough and when an adaptive rule is worth the extra
machinery. That is the gap this project addresses.

## Research Question

**When does an adaptive stopping rule beat a well-tuned fixed budget for an
autonomous shopping agent, and when is it not worth the complexity?**

The deliverable is a decision rule an engineer can apply before writing any
optimizer: given the price dispersion, merchant count, per-query cost, and budget
tightness they face, should they use adaptive stopping or not?

## Why This Is Answerable Now

Tool-using shopping agents can query machine-readable catalogs across many
independent merchants, so real cross-merchant price panels can be collected instead
of simulated. We use UCP capability records to discover catalog-search interfaces;
UCP is collection infrastructure, not the object of study. Two facts measured from
this corpus make the question tractable:

- Repeated scans of the same merchant minutes apart are byte-identical, so the
  measurement instrument itself contributes no noise.
- Across roughly one month, catalog membership turns over substantially and a
  minority of surviving SKUs move in price. Offers really are ephemeral, so
  stopping is a genuine decision rather than a formality.

Both figures are regenerated by the build rather than quoted from memory; the
numbers reported in the manuscript come from `artifacts/`.

## Benchmark

An episode is one exact SKU offered by two or more independent merchants in a
single currency. The agent queries merchants one at a time. Each query consumes a
resource vector (elapsed time, tokens, API calls, API spend) and reveals current
availability and price.

- **Commit or continue (primary).** After observing a catalog offer, the agent either
  attempts purchase immediately or continues searching. Continuing does not reserve
  the observed catalog offer; a later query is a new observation rather than a
  guaranteed recall of the earlier price or availability.
- **Held offer (robustness).** The best observed offer stays purchasable until the
  episode ends.
- An episode ends with a purchase, an exhausted merchant list, or an exhausted
  budget. Ending without a purchase is an explicit failure carrying a penalty, not
  a free outcome.

Merchant price and availability forecasts are estimated **only** from the earlier
calibration snapshot. The later snapshot is frozen as held-out panels. Unqueried
merchant outcomes stay hidden from online policies, so the exhaustive oracle cannot
leak into routing or stopping.

## Policies Compared

| Arm | Role |
| --- | --- |
| Accept first available | Resource-minimal floor |
| Fixed depth *k* | The rule engineers actually ship; *k* tuned on calibration only |
| Fixed price threshold | The other rule engineers actually ship |
| Equal split of remaining budget | Naive resource allocation |
| Myopic value of information | Queries only while the next call fits |
| Adaptive stopping (this work) | Reservation price from remaining merchants and budget |
| Exhaustive oracle | Unattainable offline bound |
| Never accept | Sanity check that failure handling is not gamed |

## Primary Outcome

Failure-penalized purchase loss per episode, compared against the strongest fixed
baseline, with paired bootstrap confidence intervals over episodes. Secondary
outcomes: purchase success rate, price regret, savings captured, and hard-budget
violations.

## Falsifiers

- If adaptive stopping does not improve purchase loss over the strongest fixed
  baseline at zero budget violations, the contribution fails.
- Any total-budget overrun is a correctness failure, never a performance tradeoff.
- Gains that vanish under paired comparison on common episodes and seeds are
  sampling noise, not an effect.
- An adaptive policy must reduce to its unconstrained counterpart when every budget
  is nonbinding; failure indicates an implementation error.
- If policies indexed only by the number of remaining merchants explain all gains,
  then resource identity is not the operative mechanism and the framing is wrong.
- Advantage thresholds derived on calibration episodes must keep their sign and
  rough magnitude on held-out episodes, or they are overfitted.
- A negative region is only reportable if it survives the same paired procedure as
  the positive region.

## Non-Goals

- Cross-episode bandit learning during the held-out evaluation.
- Parallel queries, strategic merchant behavior, and personalized pricing.
- Third-party historical price datasets.
- Multi-product baskets and multi-attribute utility. Shipping, tax, and returns
  enter only where landed price is completely observed.
- Any claim that the merchants observed here represent retail commerce generally.
